# Datasets

Three small synthetic datasets support the labs, practice exercises, mini-projects,
and capstone. They are **generated by a script in this repository**, not
downloaded. That is a deliberate choice, and this page explains what it buys, what
it costs, and how to substitute a real openly licensed dataset if you want one.

| | |
|---|---|
| **Generated by** | [`datasets/generate.py`](generate.py) |
| **Seed** | `20260101` |
| **Output** | `datasets/generated/` (not committed) |
| **Total rows** | 1,500 across three files |
| **Total size on disk** | about 100 KB |
| **Licence of the generated files** | CC0-1.0 — they contain no source data |
| **Personal data** | None. Every value is invented. |
| **Network required** | No |

---

## Why synthetic data

A course about operating models needs data with the *defects* that make operations
hard: a schema that changes, a slice with almost no positives, a distribution that
shifts halfway through a log. Real datasets are either too clean (they were
curated for a benchmark) or too sensitive (they describe people). Synthetic data
lets the course inject a fault, measure the consequence, and invite you to break
the pipeline without anyone's privacy being at stake.

The cost is equally real, and worth stating plainly:

- **Synthetic relationships are simpler than real ones.** A model that reaches
  0.83 ROC AUC here may reach 0.65 on a real cohort. Do not read the absolute
  numbers as a benchmark.
- **Synthetic drift is cooperative.** It shifts in the columns the generator
  shifts. Real drift is often in a column nobody instrumented.
- **No dataset is neutral.** The generator encodes assumptions — for example that
  attendance and engagement predict a support need. That assumption is an
  argument, not a fact, and the capstone asks you to criticise it.

For all three reasons, every lab that uses this data also asks what the result
would *not* license you to claim.

The three datasets are independent. They are *not* joins of one another, and no
`student_ref`, `trip_id`, or `reading_id` refers to a real record anywhere.

### `raviride_trips.csv`

Completed trips from the course's fictional ride-hailing company. Congestion is
a function of hour, zone, and weather, so the signal is learnable but not exact.

| Column | Type | Range / values | Notes |
|---|---|---|---|
| `trip_id` | string | `T0001`–`T0600` | Row key. **Never a feature.** |
| `trip_date` | date | 2026-01-05 onward | 20 trips per day |
| `hour` | int | 6–23 | Local hour of request |
| `weekday` | int | 0 = Monday … 6 = Sunday | |
| `zone` | category | Gulberg, Johar Town, DHA, Model Town, Saddar, Bahria | |
| `weather` | category | clear, rain, heat | `clear` is over-represented |
| `distance_km` | float | 1.2–18.0 | |
| `driver_accept_secs` | float | ≥ 4 | Time until a driver accepted |
| `eta_minutes` | float | ≥ 2 | **Target**: realised arrival time |

First two records, exactly as generated:

### `study_support.csv`

Invented term-level records for a fictional student-support programme. The label
is drawn from a logistic function of attendance, engagement, submissions, prior
band, contacts, and term, plus noise. It is not a model of any institution and
must not be used to make decisions about people.

| Column | Type | Range / values | Notes |
|---|---|---|---|
| `student_ref` | string | `S0001`–`S0400` | Sequence number, not a person |
| `term` | category | 2025-Fall, 2026-Spring | Alternating |
| `prior_gpa_band` | category | low, mid, high | Banded on purpose: bands are less sensitive than marks |
| `attendance_rate` | float | 0.35–1.0 | Fraction of sessions attended |
| `lms_logins_week` | float | ≥ 0 | Weekly learning-platform logins |
| `assignments_submitted` | int | 0–12 | Out of twelve |
| `support_contacts` | int | 0–3 | Times the student contacted support |
| `needs_support` | int | 0, 1 | **Target**: synthetic support flag |

```csv
student_ref,term,prior_gpa_band,attendance_rate,lms_logins_week,assignments_submitted,support_contacts,needs_support
S0001,2025-Fall,low,0.7660,3.2000,9,1,1
S0002,2026-Spring,mid,0.6820,7.7000,6,1,0
```

`support_contacts` is deliberately ambiguous: it is both a plausible *cause* of
being flagged and a plausible *consequence* of struggling. The capstone asks you
to decide, in writing, whether it belongs in the feature set and what the choice
costs.

### `equipment_sensors.csv`

Readings from eight fictional machines. Roughly 8% of readings are followed by a
failure within seven days. Class imbalance is intentional: a model that predicts
"never fails" scores 92% accuracy and is useless, which is the point of the
metric choice in Lab 18.

| Column | Type | Range / values | Notes |
|---|---|---|---|
| `reading_id` | string | `R0001`–`R0500` | Row key |
| `machine_id` | string | `M01`–`M08` | **Group key** — split by machine, not by row |
| `temperature_c` | float | about 50–90 | Rises with days since service |
| `vibration_mm_s` | float | about 0.2–4.5 | Rises with operating hours |
| `pressure_bar` | float | about 3.2–5.2 | Mostly noise |
| `operating_hours` | int | 200–9000 | Cumulative |
| `days_since_service` | int | 0–219 | |
| `failure_within_7d` | int | 0, 1 | **Target** |

```csv
reading_id,machine_id,temperature_c,vibration_mm_s,pressure_bar,operating_hours,days_since_service,failure_within_7d
R0001,M01,75.1000,2.6300,3.7100,1298,208,0
R0002,M02,64.4000,1.1100,4.2700,6503,161,0
```

Splitting these rows at random puts readings from the same machine in train and
test, which flatters the model. The advanced starter and MP4 split by
`machine_id` instead, and the reference solution shows both numbers so you can see
the difference.

## Generating and verifying

From the repository root:

```bash
python datasets/generate.py
python datasets/generate.py --check
```

```powershell
python datasets/generate.py
python datasets/generate.py --check
```

The first run writes the three CSV files and `generated/manifest.json`. The second
recomputes each file's SHA-256 and compares it with the manifest:

```text
$ python datasets/generate.py
raviride_trips.csv           600 rows  138a9830cd5cb541...
study_support.csv            400 rows  03f871c15e2335a5...
equipment_sensors.csv        500 rows  c795196dbedc9c77...
manifest: datasets/generated/manifest.json

$ python datasets/generate.py --check
OK       raviride_trips.csv  600 rows
OK       study_support.csv   400 rows
OK       equipment_sensors.csv  500 rows
```

Byte-identical output across platforms is achieved by rounding every float to four
decimals and writing with an explicit format. This is not free: the files are not
a bit-for-bit record of the random draw, only a stable rendering of it. That is
the correct trade for teaching, because it lets two students on different
operating systems compare hashes and mean it.

A different seed produces the same schema and approximately the same positive
rate, but different rows and hashes:

```bash
python datasets/generate.py --seed 7 --out datasets/generated-seed7
```

Changing the seed does **not** leave the default files untouched, because `--out`
defaults to the same directory. Regenerate with the default seed afterwards if
you want the course hashes back.

### What the manifest is for

`manifest.json` records the seed, the row counts, the column order, and a hash per
file. Two uses:

1. **Verification.** `--check` proves the files on disk are the ones the course
   describes, which is the first thing to rule out when a lab's expected value
   does not appear.
2. **Provenance.** A report that cites the hash can be reproduced by anyone who
   has the generator, without shipping the data.

## Repository size and what not to commit

The generated files are small (about 100 KB in total) but they are still build
output: they belong in the working tree, not in version control. `datasets/.gitignore`
ignores `generated/` and `generated-*/`. Train model binaries, MLflow stores,
Docker images, and downloaded external data are ignored for the same reason: a
repository that carries its own build products cannot be verified by cloning it.

The course's own rule of thumb:

| Artefact | Commit? | Why |
|---|---|---|
| Generator script | Yes | It is the provenance |
| Manifest | No, regenerate | Derived from the files |
| Generated CSV under 1 MB | No | Build output; regenerate in one command |
| Externally downloaded data | No | Licence and size; record the URL, licence, and SHA-256 instead |
| Trained model (`*.joblib`) | No | Reproducible from code, data, and parameters |
| Small fixture inside a test | Yes, if hand-written and tiny | Tests must run without a generation step |

## Using an external dataset instead

You may replace any dataset with a public one, provided you can answer all four
questions below. The substitution is an assessed optional task in MP2 and the
capstone; the core route does not need it.

1. **Licence.** What exactly does the licence permit — commercial use,
   redistribution, derivative works? Record the licence name and a link.
2. **Provenance.** Who collected it, when, for what purpose, and what population
   does it represent? A dataset collected from one hospital does not describe a
   city.
3. **Sensitivity.** Does it contain personal data, even pseudonymised? If yes, it
   does not belong in this course repository, whatever the licence says.
4. **Stability.** Is there a permanent identifier and a checksum? A URL that
   serves a different file next month is not a version.

### Sources that generally satisfy the licence check

| Source | Licence position | Suitable for |
|---|---|---|
| `scikit-learn` bundled datasets (`load_breast_cancer`, `load_diabetes`, `load_wine`) | BSD-3-Clause, ships with the library | Any exercise; no download |
| UCI Machine Learning Repository | Usually CC BY 4.0; **check each dataset page** | Tabular classification and regression |
| OpenML | Per-dataset licence metadata; check the dataset, not the site | Experiment tracking practice |
| `seaborn` / `vega-datasets` sample data | BSD / MIT for the package; check embedded data provenance | Visualisation and EDA only |

Do not use: scraped social media, leaked datasets, anything with real student
records, patient records, or customer transactions, or a dataset whose licence
page you cannot find. "It was on Kaggle" is not a licence.

### Documenting a substitution

Add a row to your report's data section:

```markdown
| Field | Value |
|---|---|
| Dataset | Breast Cancer Wisconsin (Diagnostic) |
| Source | scikit-learn 1.5.2, `load_breast_cancer` |
| Licence | BSD-3-Clause (bundled with scikit-learn) |
| Instances | 569, 30 features, 2 classes |
| Retrieved | 2026-10-26 |
| Checksum | SHA-256 of the exported CSV, recorded in `data/manifest.json` |
| Sensitive | No personal identifiers; features are cell-nucleus measurements |
```

If you cannot fill every row, you cannot yet defend the dataset, and the
assessment will say so.

## Frequently asked questions

**Can I commit the generated CSVs so my project runs without a generation step?**
For your own project, yes — under 1 MB and with the generator and manifest
alongside, that is a defensible choice. For this course repository, no: the
verification story depends on regeneration.

**The positive rate changed when I edited the generator. Is that a bug?**
No. The label is drawn from a probability that depends on the intercept. Changing
the intercept changes the rate. Record the new rate in your report if you keep the
change; do not quietly retune the generator to make a metric look better.

**Why is `student_ref` in the file at all?**
To practise dropping an identifier before training, and to join prediction logs
back to rows during review. It is a sequence number, not a person.

**May I use these datasets in my own teaching?**
The generated files are CC0. Attribution is not required, but a link back to this
course is the honest thing to do.
